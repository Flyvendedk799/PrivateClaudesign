## How to read this report

- The FPS run validates **defects D1–D10** documented in `docs/may9.md` §0b.
  The single most damning datum is the `validate_game_scene` / `playtest_game`
  / `assert_game_invariants` triplet at exactly **1 call each** across 28
  snapshots. The infrastructure exists; the agent does not call it.
- The brawler run is the case the saved memory note pointed at — 6 corrections
  to converge a fighting game. We don't have per-error breakdowns for it but
  the tool-call distribution (520 `str_replace` / 86 `set_todos` / 9
  `render_preview`) confirms the same pattern.
- All numbers are derived from `run_usage`, `chat_messages`, and
  `design_snapshots` tables. New columns added in may9 Phase 0
  (`artifact_type`, `engine`, `abort_kind`, `narration_dropped`,
  `prompt_version`, `first_tool_call_ms`) start populating from the next run
  written under the V2 stack and will appear in `evals/runs/2026-XX-XX.md`
  comparison reports.

See `docs/may9.md` for the full sequenced plan.

## Eval framework (may9 Phase 14)

The eval-framework runner + assertions ship in
`packages/core/src/eval/`; fixtures live under `evals/fixtures/`.
Run the framework against your local `designs.db`:

```
pnpm eval:games           # writes evals/runs/{today}.md
pnpm eval:games --print   # prints to stdout
pnpm eval:games --json    # JSON blob (for CI / scripts)
```

Fixtures bundled at first ship:

- `brawler-fight` — replays the c44763af 6-correction case; checkEngineFit must reject pygame for fighting+3d
- `fps-wave-defense` — replays the ba2adf62 28-snapshot baseline; every Phase 9b cap must hold
- `topdown-rpg-godot` — forces choose_engine fit gate on a clear Godot win
- `match3-puzzle-phaser` — Phaser puzzle baseline; tests the `puzzle` playbook end-to-end

A fixture without a matching design in `designs.db` is reported as
"(no recording in designs.db for slug ...)" with `pass=false`. The
recording workflow (run the brief, then re-run the eval) is the
intended path until the fixture-replay provider lands.
